# Offline Retrieval-Augmented Generation (RAG)

An end-to-end **offline Retrieval-Augmented Generation (RAG)** application built using **Java** and **Spring Boot**. The system allows users to upload documents, organize them into sections, perform semantic search over selected knowledge sources, and receive context-aware answers generated by a locally hosted Large Language Model (LLM).

The entire pipeline runs locally without relying on any external AI APIs.

---

# Features

* User authentication
* Upload multiple documents
* Organize documents into multiple sections
* Parse documents using Apache Tika
* Manual text chunking implementation
* Offline embedding generation
* Semantic vector search using Qdrant
* Query refinement using a local LLM
* Context-aware answer generation
* Search an entire section or only selected documents
* Delete individual documents
* Delete entire sections
* Fully offline AI pipeline

# Workflow

## Document Ingestion

1. User logs in.
2. Creates or selects a section.
3. Uploads one or more documents.
4. Apache Tika extracts text from each document.
5. The extracted text is manually split into chunks.
6. Each chunk is converted into an embedding using the Gemma Embedding Model.
7. Embeddings are stored in Qdrant.
8. Metadata such as users, sections, documents, document IDs, and chunk IDs is stored in PostgreSQL.

---

## Query Pipeline

1. User selects the knowledge source.
    * Entire section
    * Selected documents
2. User enters a question.
3. The question is refined using Qwen 2.5.
4. The refined query is embedded.
5. Qdrant retrieves the most relevant chunks from the selected knowledge source.
6. Retrieved chunks and the original query are sent to Qwen 2.5.
7. The generated answer is returned to the user.

# Knowledge Source Selection

The application supports scoped retrieval by allowing users to choose where the search should be performed.

* Entire Section
* One or more selected documents

Only the selected knowledge source is searched, improving retrieval relevance and reducing unnecessary context.

---

# Metadata Storage

PostgreSQL stores:

* User credentials
* Sections
* Documents
* Document IDs
* Chunk IDs
* Relationships between documents and sections

---

# Vector Storage

* Chunk embeddings
* Chunk payloads

# Why This Project?

This project demonstrates the implementation of an end-to-end Retrieval-Augmented Generation pipeline without relying on cloud AI services or high-level RAG frameworks. It combines traditional backend development with modern AI techniques, including document parsing, custom chunking, semantic search, vector databases, metadata management, and local LLM inference to create a scalable and privacy-focused knowledge retrieval system.
